# P0 acceptance report

Status: accepted on 2026-09-25. Product commit `0c8199c` is integrated into `main`.

P0 implements one offline request-to-verdict loop. Application code lives under `src/`. The independent acceptance suite lives under `tests/spec/`. The CLI creates one work unit, calls a scripted worker, calls a separate scripted verifier after completion, and lets the kernel decide whether verification is complete.

## Separate ownership

BP-0 authored the public contract, schemas, fixtures, acceptance tests, and harness before product implementation. PRODUCT-0 implemented the product in a separate Git worktree. The coordinator reviewed the handoff and source wiring. A separate reviewer inspected the implementation for gaps. BP-0 owns the final rerun of the pinned checks.

The product agent did not change acceptance tests, canonical schemas, public types, package configuration, or compiler configuration. The external runner checks these files by digest and uses its own test paths and TypeScript executable.

## Scope and next boundary

This is an executable deterministic foundation for P1. Verification commands are fixture labels, and evidence references are simulated. P0 does not invoke Codex, execute verification commands, edit repositories, persist runs, resume decisions, repair code, or deliver PRs.

The [README](../../README.md) provides pass and dishonest-worker examples. The [requirement map](../../tests/spec/requirements.md) identifies the proof for each P0 gate.
