|---|---|---|

| P5-006 | Exact-head/provider required CI, honest pending/failed/stale states and full object-page pagination | Eleven-case CI matrix, multiple required pairs, closure between reads, pending-to-pass-to-fail, malformed/error responses, known-bad CI oracle |

| P5-LIVE | Actual authorized issue, HTTPS push, one real PR, exact-head required CI, restart and credential boundary | `LIVE.md`, `harness/live-proof.mjs`, coordinator review of retained evidence |

Seven sanity checks establish the real Git fixture, create-only conflict rejection and plain-push unsafe control, pinned-base/new-file mode policy, strict configuration, paginated fake gateway, independent CI policy, event replay defects, partial-feature rejection, coherent noncanonical URL rejection and a valid-then-tampered historical intake capture. The same public CLI drives all 64 product scenarios. The fake GitHub transport records calls and durable fact snapshots; Git and the bare remote are real.

The supported representation and repeated-check limitations are explicit contract scope. A missing live destination does not become a passed check. Scaffold-only red is preparation; definitive red needs the independently runnable-green prior candidate and pinned reports.
